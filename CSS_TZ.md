## 1. Структура css/

- `css/base.css` — пишется командой вместе: палитра, шрифты, `header`/`nav`/`main`/`footer`.
- `css/author-a.css` — личный файл автора A (index.html, stores.html, reviews.html).
- `css/author-b.css` — личный файл автора B (shoes.html, clothing.html, accessories.html).
- `css/author-c.css` — личный файл автора C (sportswear.html, electronics.html).
- Порядок подключения на КАЖДОЙ странице: сначала `base.css`, потом свой личный файл.

## 2. Селекторы — распределение, чтобы не было пропусков

| Селектор | Кто использует | Где логично |
|---|---|---|
| Type selector | все | базово везде |
| Class | все | обязательно ≥8 классов суммарно, с осмысленными именами |
| ID | все | ≥2 на сайт, 1 раз на странице — с комментарием "почему id" |
| Descendant | A | `nav ul li` — стилизация вложенного списка категорий |
| Child (`>`) | B | прямые дети товарной таблицы/карточек |
| Adjacent sibling (`+`) | C | например `h2 + p` — отступ первого абзаца после заголовка |
| Grouping (`,`) | A | группировка однотипных заголовков секций |
| Attribute selector | C | например `input[type="tel"]` в форме заказа |
| Universal (`*`) | база (base.css) | сброс box-sizing |
| `:hover`, `:focus` | все | обязательно на ссылках nav + полях форм |
| `:first-child` / `:nth-child` | B | зебра-раскраска строк таблицы товаров |
| `::before` / `::after` | A | декоративный элемент, например кавычка перед `blockquote` |

## 3. Классы и ID

- Минимум 8 классов, минимум 2 id — суммарно по сайту, не обязательно поровну.
- Имена — по смыслу, не по виду (`.price-card`, `.store-list`, `.order-form` — хорошо; 
  `.red`, `.big`, `.box1` — штраф 2 балла каждое).
- На каждый id — комментарий в коде, почему тут нужен именно уникальный id, а не класс 
  (например, `#order-form` — единственная форма на странице, к ней может вести якорная ссылка).

## 4. Цвета, шрифты, отступы — кто решает

Это делает команда вместе в `base.css`:
- ≤5 цветов, с комментарием-обоснованием каждого (например, привязка к цветам Kaspi/логотипа аккаунта).
- Обязательно: hex + rgb/rgba + один именованный цвет (`crimson`, `teal` и т.п.).
- 2 семейства шрифтов с полным fallback-стеком.
- `box-sizing`, `margin`, `padding`, `border` осознанно + комментарий про пойманный margin collapse.

## 5. Демонстрация каскада (ровно 1 раз на весь сайт каждое)

- **1 внутренний `<style>` блок** — на `index.html` (автор A), комментарий "зачем показываем каскад здесь".
- **1 инлайн `style=""`** — на любой из товарных страниц (автор B или C), с комментарием, что именно он переопределяет.
- **1 `!important`** — там же или рядом, с комментарием-обоснованием, почему без него не обойтись.

## 6. Flexbox (обязательно на своих страницах у КАЖДОГО автора)

- `nav` — flex row с `justify-content`, `align-items`, `gap` — в `base.css`, общий для всех.
- Дополнительный flex-блок у каждого автора:
  - **A** — карточки шагов "Как это работает" на index.html.
  - **B** — ряд карточек товаров на shoes.html/clothing.html/accessories.html.
  - **C** — ряд карточек брендов на sportswear.html.

## 7. Grid (обязательно на своих страницах у КАЖДОГО автора)

- **A** — grid-раскладка карточек стран/магазинов на stores.html.
- **B** — grid брендов на shoes.html, clothing.html и accessories.html
- **C** — grid брендов на sportswear.html или electronics.html.

- Комментарий у каждого: почему тут grid лучше подошёл, чем flexbox.

## 8. Positioning, float, clear — распределение по сайту (см. открытый вопрос 0)

- **static** — объясняется комментарием в base.css (просто указать на обычный элемент).
- **relative** — автор B, как containing block для бейджа "Скидка"/"Последний размер" на карточке товара.
- **absolute** — тот же бейдж внутри relative-родителя у автора B.
- **fixed** — автор A, например кнопка/полоса "Написать в WhatsApp" на index.html, которая остаётся на экране.
- **float + clear** — автор A или C, изображение внутри абзаца текста (например, фото на reviews.html или sportswear.html) с обтеканием и явным `clear`, плюс комментарий, что было бы без `clear`.

- **grid** или **absolute + transform** — автор C (например, центрирование бейджа/лого на sportswear.html).
- Комментарий у каждого: какая техника и почему подходит именно этому случаю.
